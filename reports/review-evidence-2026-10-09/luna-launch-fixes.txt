CephVR Luna launch fixes — 2026-10-09

Scope and design

Implemented the supervisor launch replay-retention and acquisition-camera worker retirement fixes under ARCH-002, E06 and E08. LaunchRegistry now retains RELEASED launch commands for the configured command_retention_ns window. For work-scoped launches the retention clock starts at max(exact release time, work finalization time), and exact active work pins its launch record. It prunes only expired RELEASED records; if capacity is full of active or still-retained records, admission fails with LAUNCH_CAPACITY. This avoids premature replay loss and avoids capacity-based eviction. The registry receives the existing configured retention value from runtime; shared command default is reused rather than adding a second policy default.

Camera retirement now requires an explicit ConfirmLaunch request carrying typed retained Cleanup operation and lifecycle evidence. The acquisition coordinator validates the exact registered resource/output catalogue and Cleanup evidence, waits for exact process exit, then sends the proof. The supervisor independently verifies exact owner/child/launch/work binding, empty native job and process absence before release. GetLaunchState remains observational. Workless session Configuration retirement is represented explicitly and does not fabricate a work identity. Failed recording output closure is accepted only when cleanup evidence shows the output was discharged; unconfirmed closure is rejected. Firmware uploader cleanup semantics remain distinct, and persistent renderer ownership remains excluded.

Extracted launch request validation and camera proof structure checks into focused modules to keep registry ownership cohesive and avoid growing an already large registry. No whole-runtime back-reference or duplicate resource inventory was introduced. Proto source was updated and generated sources regenerated with the repository generator.

Post-review retirement-race correction (2026-10-09)

Closed the Supervisor health race by sending one exact ConfirmLaunch Cleanup proof before Shutdown and replaying the identical request after process exit. The first confirmation validates proof and the exact live job/process, then retains the canonical proof on that exact launch without release. The second can release only after independent empty-job and process-absence checks. Health continues to record CHILD_EXITED, but suppresses only safety escalation for that exact launch when its validated proof is retained. Unacknowledged camera exits still escalate; native inspection failures and acquisition-owner authority/heartbeat loss retain existing escalation paths. The same original coordinator absolute deadline covers proof acknowledgement, Shutdown, process-exit wait and final confirmation; no new deadline or state enum was introduced.

Added regressions for lifecycle/health classification in the exit-before-final-confirm interval, unacknowledged exit escalation, proof immutability, same-request replay, both session/manual callers, and a hung worker that returns failure after the original deadline without a second confirmation. Sol and Astra reviewed the proposed design and agreed on the no-new-deadline approach; final acceptance is pending.
