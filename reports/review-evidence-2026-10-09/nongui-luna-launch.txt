# Registered worker launch refactor handoff

Date: 2026-10-09
Repository: `/Users/pedrocastelhanito/Dev/reiter-software/reiter-cephalopod-vr-2.0-software`
Scope: Shared Windows worker launch ordering under E08 for acquisition and Visual Stimulus. No GUI code or hardware execution.

## Changes

- Added `src/cephvr/platform/windows/worker_launch.py`, a generic typed handshake that owns only parent pipe handles and ordering: exact PlanLaunch receipt, pipe creation, suspended native child creation, exact OS confirmation, backend peer registration, resume, retained bootstrap writer, and Operational polling under the caller's original absolute deadline.
- Moved the blocking bootstrap writer into `src/cephvr/platform/windows/bootstrap.py`. Its attempt remains held by the backend cleanup list while incomplete; consumed write handles stay with the writer. A failed thread start closes both parent handles. Confirmed child/job ownership remains backend/native-owned.
- Updated acquisition and Visual Stimulus launchers to supply backend-specific requests, descriptors, auth, native operations, and state queries to the helper. Acquisition and Visual Stimulus preserve their own process/job and credential ownership.
- Updated Visual Stimulus startup cleanup to drain completed writes using the original launch deadline.
- GetLaunchState must echo the planned payload and the exact PID/creation time confirmed with the supervisor. CLEANUP_REQUIRED, RELEASED, missing endpoint, identity mismatch, and wrong state type fail startup.
- Native creation failure is reported to the supervisor only after positive empty-job inspection. Failed/unknown inspection retains the unresolved launch state without asserting that no child exists.
