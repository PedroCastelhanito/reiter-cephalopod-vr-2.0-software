# CephVR2.0 backend review findings (read-only, tool-first pass)

Generated 2026-10-08 at HEAD `e4c653c` plus uncommitted work (`src/cephvr/gui`, `TODO.md`, `architecture.md`). No code, architecture record, TODO or LOG was edited.

## How this table was produced

The workflow-based review (Haiku scanners, Sonnet reviewers, Opus decision) was stopped after repeated usage-limit failures. This table replaces it with a cheaper pass:

1. **Free tooling at HEAD:** ruff (baseline and an extended rule set), `ruff format --check`, mypy `--platform win32` per backend, the boundary tool, the portable pytest suite, an AST scan for silent broad exception handlers, a name-reference scan for dead code and a name-in-tests scan for untested modules, and greps for cross-backend conventions.
2. **Salvaged reviews:** the Sonnet reviews that completed before the stop (launcher, client, supervisor, shared, cross-backend; 34 findings, reviewed at baseline `5c24d99`). Each is tagged `re-verified at HEAD`, `file unchanged`, or `not re-checked at HEAD`. **347 files changed between that baseline and HEAD** (mostly the new GUI, but also ~9k added lines across the backends), and the first review's High finding (acquisition PlanLaunch missing the child token) was already fixed in commit `aff8e0c` on 2026-10-06, so it is dropped.
3. **Not included:** the 124 Haiku scanner results from the stopped run were never verified by a reviewer and their line numbers are stale. They are kept in `salvaged-journal.json` but are not table rows. Controller, tracking, acquisition, visual_stimulus and platform had **no model review**; their rows come from tools only.

## Review limits

- **Coverage is uneven.** Only launcher, client, supervisor, shared and cross-backend had a model review (baseline `5c24d99`). Controller, tracking, acquisition, visual_stimulus and platform findings come from tools and may miss logic defects, races and contract mismatches that need reading.
- **Staleness.** Salvaged findings marked "not re-checked" may be fixed or moved; check each before applying. Line numbers from the salvaged reviews are approximate.
- **Heuristics.** The silent-handler scan flags handlers with no raise and no call and no nearby comment; some are intended best-effort cleanup. The dead-code scan counts name occurrences across `src`, `tests` and `tools` only, so names used dynamically or documented in `docs/`/`contracts/` could be false positives. The untested-module scan only checks whether a module name appears in any test file, so indirect coverage is invisible.
- **Excluded scope.** `src/cephvr/gui` and `src/cephvr/synchronization` (in progress or deferred), generated `v1/` directories, firmware, analysis and offline replay.
- **Not run.** No `pytest --cov` (pytest-cov is not installed), no vulture/radon (not installed; I did not install packages), no Windows or rig checks.
- **Decision IDs** are cited from the reviewers' reading of the architecture records and from `architecture.md`'s register; I did not re-read every decision page in this run.
- The flaky test was observed once in the full run and passed 3 of 3 alone, so its cause (timing under load) is inferred.
